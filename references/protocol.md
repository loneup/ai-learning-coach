# 学习协议（完整版）

> SKILL.md 是精简工作流；本文件是完整方法论与边界。每次辅导前通读一遍，重点核对「证据标准」与「交接纪律」。

## 一、为什么「先动手后读书」

- 成人学习的动力来自「有用」：先遇到真实痛点，理论才有落点；
- 动手产出（小任务/演示/讲稿）本身就是证据，读书不是证据；
- 顺序固定：小任务（20–40 分钟）→ 痛点日志 → 补理论 → 费曼讲清 → 3 追问自测。

## 二、五步学习循环（每个模块都走）

1. **输入**：读指定章节 / 官方文档 / 课程对应章节；
2. **动手**：做一个真实小任务或小项目（不虚构）；
3. **输出**：写一页「我能讲清什么」，讲给 AI 听（费曼）；
4. **教学**：讲给学员/同事（能教才算真懂）；
5. **复盘**：痛点日志四行 + 周报，升级或标「待验证」。

## 三、证据标准（升级的唯一依据）

| 证据类型 | 含义 | 可链接形式 |
|---|---|---|
| 痛点日志 | 踩过的坑及解决过程 | `证据库/` 下日志文件 |
| 产出物 | 亲手做出来的东西 | 文件/链接/截图 |
| 演示记录 | 亲手演示的过程记录 | 录屏/记录/见证人 |
| 通关勾选 | 任务卡三关打勾 | 任务卡文件 |
| 教学记录 | 讲给他人听的记录 | 课程记录/反馈 |

规则：没有证据的条目只能标「进行中」或「待验证」；AI 不得把「看过资料」升级为「已掌握」；等级升级必须附证据链接。

## 四、三关及格线与等级

- **三关**：能讲清 5 分钟（脱稿）/ 能亲手演示 / 能答 3 个追问；
- 教学线 L0.1–L0.4：基础通关 → 方向带教 → 迁移认证（设计新课）→ 讲师认证（带新讲师）；
- 知识线 1–4 级：1 入门（知道是什么）→ 2 会用（独立完成小任务）→ 3 能独立做（完成完整项目并解释取舍）→ 4 能教（脱稿讲+演示+答疑+设计练习）；
- 两条线独立但互相引用证据；未跑通不上台（演示案例未达标就降级为回放/录屏）。

## 五、21 天速成节奏（阶段 0）

- 每天：1 个真实小任务跑通 + 1 条痛点日志 + 费曼 10 分钟 + 自测 3 追问（每日固定约 30 分钟）；
- 第 1–7 天：六模块 M1–M6 逐个通关，Day 7 完成 L0.1 基础通关自测；
- 第 8–21 天：D1 官网信息条 → D2 真机切片 → D3 三轮回稿 → D4 首条样片 → Day 21 总验收；
- 长期（1–12 月）：按知识地图 12 领域逐级学习，每领域达「能讲清+能演示+能答疑」后升级。

## 六、跨 AI 交接纪律

1. 接手顺序不可跳：AGENTS → SYSTEM → HANDOFF → PROFILE → 00/01 → 当天任务卡；
2. 三件套必须一致：PROFILE（档案，version+1 + Changelog）→ SYSTEM（现状快照）→ HANDOFF（最近完成/下一步/最需要注意）；
3. 只记录真实完成；交接时 HANDOFF 缺「下一步」或「最需要注意」视为未交接；
4. git 提交规范：`YYYY-MM-DD 类型: 简述`；有问题先 `git log --oneline` / `git diff HEAD~1` / `git show <commit>`，回退用 `git checkout <commit> -- <文件>` 只恢复单个文件；
5. 多端冲突时以最新 HANDOFF.md 为准手工合并，合并后注明并提交；
6. 发给新 AI 的最小话术：**「先读 AGENTS.md 和 PROFILE.md，辅导我，结束时按更新协议更新三件套并提交。」**

## 七、边界（AI 必须遵守）

- 可以：更新三件套；整理资料；出练习题与自测题；复盘痛点日志；按知识地图规划模块；
- 先确认再动：修改 AGENTS 稳定规则；改体系设计；改变学习顺序或目标；把「待验证」改为「已掌握」；
- 绝对不要：编造证据、夸大进度、删除历史记录、把未亲手验证的内容写成事实、代替学员做关键决策。

## 八、常见陷阱

- **把「读完了」当「学会了」**：必须补动手证据；
- **AI 代答自测题**：只能提问和反馈，不能把答案喂给学员；
- **漏更新三件套**：结束前逐项核对 PROFILE/SYSTEM/HANDOFF 三者一致；
- **忘记 git 提交**：历史即证据，漏提交等于断档；
- **把「待验证」写成「已掌握」**：违反证据规则，宁可低估不可高估。
